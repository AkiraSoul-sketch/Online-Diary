# Онлайн дневник. Спецификация сервиса.

## Работа с журналом.

#### Diary maintainer.

Описание: Сущность `Diary maintainer` - это обладатель журнала, который имеет доступ к определённому журналу. Есть возможность редактировать журнал, выставлять оценки, создавать тему, комментировать оценки, редактировать оценки.

#### Diary.

Описание: Сущность `Diary` - это журнал. В нём хранятся оценки, можно группировать оценки. Он имеет дату создания, дату последнего обновления и дату архивации. Так же его можно заблокировать. Он нужен для группировки оценок.

#### Diary access.

Описание: Сущность `Diary access` - это доступ к журналу. Нужен для более лучшей работы с журналом, позволяет привязать: одного человека к нескольким журналам или привязать один журнал к нескольким людям.

### Модель даннных:

_Diary maintainer_:

Id, created_at, updated_at, deleted_at, archived, name, surname, parentname.

_Diary_:

id, id_discipline, id_group, locked_at, created_at, updated_at, archived.

_Diary access_:

id_maintainer, id_diary, access_type.

### Функционал (API) в рамках журнала:

1.`create_maintainer()` - Создать обладателя. Создает обладателя журнала без привязки к журналам.

2.`edit_maintainer()` - Редактировать обладателя. Позволяет изменить данные обладателя.

3.`archived_maintainer()` - Архивировать обладателя. Архивирует обладателя, делая его не доступным для использования.

4.`create_diary()` - Создать журнал. Создает журнал, привязанный к обладателю.

5.`edit_diary()` - Редактировать журнал. Позволяет изменить данные журнала.

6.`archived_diary()` - Архивировать журнал.

7.`give_diary_access()` - дать доступ к журналу.

8.`take_diary_access()` - взять доступ к журналу.

9.`revoke_diary_access()` - отозвать доступ к журналу.

10.`chance_access()` - изменить доступ к журналу.

11.`read_diary` - прочитать данные с журнала.

12.`lock/unlock` & `diary`

### Правила: 

1. Для одного `maintainer` есть доступ к чтению другого `diary`, но нет доступа на редакцию другого `diary`.
2. Для каждого `diary` есть определенная `group_id` и `discipline_id`, в рамках системы должна быть уникальная связка `group_id` и `discipline_id`.
3. `Diary`, который в статусе `block`, его нельзя `edit`, его можно только `unlock`

1. Журнал с оценками. (Преподаватель должен открывать, только журнал по своим дисциплинами. При этом препод, не может редактировать журнал с оценками не по своим дисциплинам).
2. Профиль преподавателя. (Личные сообщения, чтобы с преподом могли связаться насчёт оценки. Также, можно поставить свои контакты, чтобы с ним связались где-то в другом месте (VK, Gmail, MAX)).
3. Выставление оценки. (был или нет студент: Н, У. Б), (оценки на выбор: 2, 3, 4, 5 или +).
4. Комментарии. (Комментировать оценки, чтобы препод мог написать по какой причине выставлено Н или 2).

**Журнал преподавателя:**
```
1. Редактировать темы по данной дисциплине. (Должна быть функция, которая позволит по данной дисциплине удалять и изменять тему).
2. Создавать тему по данной дисциплине. (Должна быть функция, которая позволит создавать темы по данной дисциплине САМИМ преподам).
3. Под цветком у оценок (Если 2 — красный, если 5 — зелёный).
4. Редактировать оценки (Если у студента была Н, но он сдал тему, препод может изменить ему на 5 спустя время).
```

Студенческая группа:
1. Это сгруппированная студенческая группа, которая называется под названием (ПСК-3-25) и в ней находятся студенты.

Студенты:
1. Могут просматривать журнал по дисциплины препода. (не могут редактировать темы и оценки в журнале).
2. Могут связаться с преподавателями насчёт оценки.
3. Могут указать свои контакты (VK, Gmail, MAX).
4. Каждый студент будет под своим уникальным ID (последние 6 цифр из студенческого билета), (не могут зайти под другим ID).
5. Успеваемость в личном профиле студента по поводу различных дисциплинам.

Администрирование.
1. У админа, должна быть статистика, где показывается текущий трафик на сайте. (Кто присутствует на сайте, сколько пользователей, насколько много действий сделано на сайте).
2. У админа должен быть управление пользователями, управление дисциплинами (переименовать дисциплину, пользователя и тд).
3. У админа должен быть доступ к открытию ЛЮБОГО профиля, ЛЮБОГО журнала и ЛЮБОЙ базы, поскольку он админ.
4. У админа, всегда должен быть доступ к созданию нового пользователя на сайте.
